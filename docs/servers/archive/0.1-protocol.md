- Scope change on 2026-11-12: the separate lobby server was dropped and the existing online lobby is kept (D6, D7). The spec was rewritten: the lobby link, tokens issued by a lobby, and the heartbeat are gone; the gate, the pass and section 5 are new. Checked against the code for this version: the ladder fields and list request in `PeerThread.cpp`, the list loop in `LobbyUtils.cpp`, the two join refusals in `WOLLobbyMenu.cpp`, and the match start hook in `StagingRoomGameInfo.cpp`.
- Left to do: nothing.
- Surprises and open questions:
  - Engine commands carry no length on the wire. A relay cannot split a packet into commands without the engine's parser, so the spec gives each command its own length-prefixed record instead of forwarding engine packets.
  - With no packet router, `ConnectionManager::ackCommand` reaches a crash assert. Server mode must bypass the acknowledgement path entirely, which the ENet link makes possible.
  - Run-ahead is calculated by the packet router today (`ConnectionManager::updateRunAhead`). The leader slot keeps that working until Phase 3.
  - A lobby with a ladder address the client does not know cannot be joined, and is listed as an unknown ladder. This existing behaviour is why the ladder fields make a good tag.
  - Eight assumptions are listed in PROTOCOL.md section 10 and assigned to packages.
- Review findings and fixes: reviewed against the engine code on 2026-11-12. 17 findings, all addressed in PROTOCOL.md:
  - Control messages and records were on separate channels, so a `DROP` could overtake the records before it. Now one ordered channel.
  - `last_frame` came from an unchecked frame number. The relay now tracks `next_frame` per slot and enforces a frame window.
  - A lobby member could take another player's slot with a self-declared id. Replaced by a private one-use join token per slot; `profile_id` removed.
  - `PLAYERLEAVE`, `RUNAHEAD` and `DESTROYPLAYER` act on fields the relay did not check. Added per-type checks on relay and client; `DESTROYPLAYER` is no longer carried and clients apply it locally on `DROP`.
  - No recovery from a connected player who stops sending. Added loading and stall timeouts on the relay.
  - Header tags differ per command type. Added the exact table and made the tag list per type mandatory.
  - Destinations are now set by the relay for synchronized commands, not by the sender's mask.
  - Ping is timed by the relay with its own nonces, not taken from ENet.
  - Custom maps would have relied on map transfer. Transfer is now switched off in both places that decide it.
  - The tag is defined as text plus a non-zero port; the client treats its region tags as known ladders; the score screen no longer reports to the tag.
  - Match start flow written out step by step, including the private message format and what happens on failure.
  - A pass now has an id, allows one live match connection, and its address comparison is always on outside a test option.
  - Missing limits added with numbers.
  - Drop and leave edge cases written out.
  - "Gate" meant two things. The relay check is now called "entry check".
  - OVERVIEW corrected: the existing lobby still shares player addresses, and a slow player still slows others until Phase 3.
  - Not verified by the reviewer and carried as assumptions: V5, V7, V8.
