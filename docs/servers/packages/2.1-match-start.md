## Done when

- [ ] In a server lobby Start is unavailable with fewer than 2 human players.
- [ ] In a server lobby the client opens no player-to-player connections and does not need the mesh to start: `StartPressed()` skips its "players are still connecting" test, and the host's connectivity check completes from the service's immediate answer.
- [ ] Host: when the countdown ends in a server lobby, the client does not send the start message yet. It runs the entry check silently if its pass has less than 60 seconds left, connects to the region's relay and sends `CREATE` for the human slots, showing "Contacting server".
- [ ] Host: on `CREATED` it posts `field` 19 with the session id and one token per other human slot, and sends the normal start message only after the service answers `result` 1.
- [ ] Host: a refused silent check, a refused or timed-out `CREATE` (10 seconds), a refused or unanswered `field` 19 (5 seconds), or a lobby membership change before the start message, closes the relay connection, shows a message, and leaves the lobby open with Start enabled.
- [ ] Every client: after the start message, `REFUSE` from the relay or no `START` within 45 seconds closes the relay connection, shows "Could not join the match.", leaves the lobby and returns to the lobby list (PROTOCOL.md 5.4 step 10).
- [ ] Member: the start message's `server_session`, `server_slot` and `server_token` are read without breaking the existing parse. A member runs the entry check silently if its pass has less than 60 seconds left, connects and sends `JOIN`.
- [ ] Member: a start message without those fields in a server lobby, a refused silent check, or a refused `JOIN`, shows "Could not join the match." and returns to the lobby list.
- [ ] Every client launches the match only on the relay's `START`, with server mode set and the relay link attached before the player list is parsed. `NGMPGame::launchGame` does not seed latency from the mesh in server mode.
- [ ] Online lobbies start exactly as before.
- [ ] Join tokens and the session id are never written to a log. Today the client logs every HTTP request body (`HTTPRequest.cpp`) and every received WebSocket message (`WebSocket::Tick`): the `field` 19 body and a start message that carries `server_token` are left out of those log lines.
- [ ] Everything is behind `RTS_SERVERS`.
- [ ] Live check, if the game data is installed: two instances go from the Servers button to a running match through a local lobby service and a local relay. Otherwise this item stays open with the note "pending: needs the game installed".
- [ ] The checks for this program in STANDARDS.md, "Before a package is done", pass.
- [ ] Reviewed by someone other than the author.
