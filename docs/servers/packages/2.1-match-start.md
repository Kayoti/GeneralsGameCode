# 2.1 Match start from a server lobby

State: done
Branch: servers-go-2.1

## Goal

When the host of a server lobby starts the match, every client connects to the relay with its own join token and the match runs through the relay.

## Depends on

C2, C3, D3, L6. C3's way of launching an `NGMPGame` in server mode is reused.

## Done when

- [x] In a server lobby Start is unavailable with fewer than 2 human players. — `StartPressed` refuses with a message when `countServerLobbyHumans() < 2`; `updateServersMatchStart` also force-disables the Start button for the host in that case.
- [x] In a server lobby the client opens no player-to-player connections and does not need the mesh to start: `StartPressed()` skips its "players are still connecting" test, and the host's connectivity check completes from the service's immediate answer. — the test is wrapped in `if (!inServerLobby())`; the existing `SendData_StartFullMeshConnectivityCheck` path is unchanged and the service answers 28 at once (SERVICE.md 10).
- [x] Host: when the countdown ends in a server lobby, the client does not send the start message yet. It runs the entry check silently if its pass has less than 60 seconds left, connects to the region's relay and sends `CREATE` for the human slots, showing "Contacting server". — countdown-end hook in `WOLGameSetupMenuUpdate` shows "Contacting server" and calls `ServersMatchBeginHost`, which renews the pass when `needsRenewal()` then opens `ServerLink::create(hostSlot, slotMask, 10s)`.
- [x] Host: on `CREATED` it posts `field` 19 with the session id and one token per other human slot, and sends the normal start message only after the service answers `result` 1. — `updateHostCreate` stores the tokens and calls `postServerSession` (`SendServerSession`); `updateHostField19` sends `SendData_StartGame` only on `FIELD19_STORED`.
- [x] Host: a refused silent check, a refused or timed-out `CREATE` (10 seconds), a refused or unanswered `field` 19 (5 seconds), or a lobby membership change before the start message, closes the relay connection, shows a message, and leaves the lobby open with Start enabled. — all map to `matchTerminal(SERVERS_MATCH_ABORTED, ...)`; the menu re-enables Start/Back/Communicator and shows the message. `rosterChanged()` guards each host step; `ServerLink::create`'s 10s timeout yields a LOST event; `postServerSession` has a 5s timeout.
- [x] Every client: after the start message, `REFUSE` from the relay or no `START` within 45 seconds closes the relay connection, shows "Could not join the match.", leaves the lobby and returns to the lobby list (PROTOCOL.md 5.4 step 10). — the member waits for the relay with a 45s `join` timeout; a REFUSE/LOST/timeout before the slot is held -> `SERVERS_MATCH_FAILED` -> `GSMessageBoxOk` + `PopBackToLobby`. A REFUSE/LOST after the slot is held (post-launch) is handled by C2's `updateServerMode` (clears the game). See the handoff note on the launch point vs `START`.
- [x] Member: the start message's `server_session`, `server_slot` and `server_token` are read without breaking the existing parse. A member runs the entry check silently if its pass has less than 60 seconds left, connects and sends `JOIN`. — read with `jsonObject.value/contains` in the `START_GAME` case; `ServersMatchBeginMemberFromStartMessage` renews the pass when needed then opens `ServerLink::join`.
- [x] Member: a start message without those fields in a server lobby, a refused silent check, or a refused `JOIN`, shows "Could not join the match." and returns to the lobby list. — all map to `matchTerminal(SERVERS_MATCH_FAILED, couldNotJoinText())`; `updateServersMatchStart` shows it and `PopBackToLobby`.
- [x] Every client launches the match only on the relay's `START`, with server mode set and the relay link attached before the player list is parsed. `NGMPGame::launchGame` does not seed latency from the mesh in server mode. — `launchGame` takes the link, `setServerMode`+`attachServerLink` before `initTransport`/`parseUserList`, and skips the mesh seed. The launch reuses C3's ordering: the client launches on `WELCOME` and leaves `START` for C2's connection manager, which gates all records on `START`. See the handoff note (documents vs. C2's uneditable `m_serverStarted`).
- [x] Online lobbies start exactly as before. — the `START_GAME` handler and the start-message callback fall through to `launchCurrentNGMPGame` (the former inline code) for a non-server lobby; `launchGame`'s server path is skipped when the link is null.
- [x] Join tokens and the session id are never written to a log. — `HTTPRequest.cpp` redacts a body containing `server_session`; `WebSocket::Tick` redacts an inbound message containing `server_token`.
- [x] Everything is behind `RTS_SERVERS`. — every new game-side path is inside `#ifdef RTS_SERVERS`; the switch-off build was verified.

- Surprises and open questions:
  - Launch point vs. `START` (documents vs. code): PROTOCOL 5.4 step 8 / Done-when 9 read "launch on the relay's
    `START`". C2's `ConnectionManager` (Must-not-edit) only sets `m_serverStarted` when it processes the `START`
    event itself, and gates every outgoing record on it. If this package consumed `START` to launch, the
    connection manager would never start. So, reusing C3's `launchServersDirect` ordering (the package says to),
    the client launches on `WELCOME` (member) / after the start message (host) and leaves `ROSTER`/`START`
    queued for the connection manager, which sets `m_serverStarted` on `START`. The *match* (any record traffic)
    still begins only on `START`; the `launchGame` call is a frame or two earlier, during loading. The pre-launch
    REFUSE/timeout path is in this package; a post-`WELCOME` REFUSE/LOST is handled by C2 (clears the game,
    returns to the lobby). PROTOCOL 5.4 section 10 / SERVICE 14 hold under this reading.
  - `server_session`/`server_slot`/`server_token` are read with `jsonObject.value(...)` and `.contains(...)`
    rather than by extending the strict `WebSocketMessage_StartGameResponse`, so an Online lobby's start message
    (no server fields) is unaffected.
  - Token/session values are validated in `ServersMatchSetStartFields` (hex, non-zero, slot 0-7) before use.
