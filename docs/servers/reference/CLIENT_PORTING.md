# Generals Online client: reference for porting Servers mode

Source: Generals Online client at commit `6ff404436` (branch `servers-go` starts there). Earlier work: branch `servers` (based on `upstream/main` `8aaa4f731`).
Paths starting with `Menus/` are under `GeneralsMD/Code/GameEngine/Source/GameClient/GUI/GUICallbacks/Menus/`.
Paths starting with `GO/` are under `GeneralsMD/Code/GameEngine/{Include,Source}/GameNetwork/GeneralsOnline/`.
"Service" means the Generals Online web service (HTTPS API + WebSocket), which is not in this repository.

Important context before anything else:

- `servers-go` forked from upstream at `e760b3695` (26 Jul 2026). `upstream/main`, which the `servers` branch is built on, is 472 commits newer. So `git diff upstream/main servers-go` mixes two things: Generals Online's own changes and upstream drift. To see only Generals Online's changes use `git diff --ignore-cr-at-eol e760b3695 servers-go -- <file>`. Several files also differ by line endings only; always add `--ignore-cr-at-eol`.
- Example of drift: `Core/GameEngine/Source/Common/CommandLine.cpp` does not exist on `servers-go`. Upstream moved it to Core after the fork (`bf9099f2a unify(commandline)`); on `servers-go` it is still `GeneralsMD/Code/GameEngine/Source/Common/CommandLine.cpp`.

## 1. Player journey

1. **Main menu, Multiplayer > Online.** `Menus/MainMenu.cpp`, `MainMenuInit` binds `onlineID = nameToKey("MainMenu.wnd:ButtonOnline")`, `networkID = "MainMenu.wnd:ButtonNetwork"`. `MainMenuSystem`, branch `controlID == onlineID`, calls `StartPatchCheck()`. Generals Online's only edits in this file are `HandleCanceledDownload` (calls `NGMP_OnlineServicesManager::GetInstance()->CancelUpdate()`) and `quitCallback`.
2. **Service init and version check.** `Core/GameEngine/Source/GameNetwork/GameSpy/MainMenuUtils.cpp`, `StartPatchCheck`: refuses ARM CPUs, calls `NGMP_OnlineServicesManager::CreateInstance()` and `->Init()`, checks the anticheat plugin (`AnticheatPlugInterface::IsPluginLoaded/IsExternalProcessRunning/DidPluginFailToLoad`), then `NGMP_OnlineServicesManager::StartVersionCheck` (`GO/OnlineServices_Init.cpp`). The version check POSTs the CRC of the running exe (`execrc`), `GENERALS_ONLINE_VERSION`, `GENERALS_ONLINE_NET_VERSION`, `GENERALS_ONLINE_SERVICE_VERSION`. If an update is required a patch download starts (`StartDownloadUpdate`, `LaunchPatcher`). Under `USE_TEST_ENV` or `USE_DEBUG_ON_LIVE_SERVER` the "needs update" answer is ignored. On success `startOnline()` (static, same file) pushes `Menus/GameSpyLoginProfile.wnd` (the `#else` branch of `#if !defined(GENERALS_ONLINE)`); `SetUpGameSpy` is not called.
3. **Login.** `Menus/WOLLoginMenu.cpp`, `WOLLoginMenuInit` (layout `GameSpyLoginProfile.wnd`) calls `NGMP_OnlineServices_AuthInterface::RegisterForLoginCallback(NGMP_WOLLoginMenu_LoginCallback)` and `BeginLogin()`. No user input is needed. `GO/OnlineServices_Auth.cpp`:
   - `BeginLogin` posts the saved refresh token to endpoint `LoginWithToken` (`GetCredentials` reads `GeneralsOnlineData/credentials.json`; in a `_DEBUG` build against the DEV environment the file is `credentials_dev_env_<instance>.json`, `GetCredentialsFilePath`).
   - Without a valid token, `DoFullLoginFlow` gets a code from `LoginCode`, opens `https://www.playgenerals.online/login/?gamecode=...` in the browser (`ShellExecuteA`; not in `_DEBUG` DEV builds), and `Tick` polls `CheckLogin` with `client_id = GENERALS_ONLINE_CLIENT_ID`, machine GUID, MAC, volume serial, exe CRC and INI CRC.
   - `NGMP_WOLLoginMenu_LoginCallback` -> `checkLogin()` sets `nextScreen = "Menus/WOLWelcomeMenu.wnd"` and pops.
4. **Welcome screen.** `Menus/WOLWelcomeMenu.cpp`, `WOLWelcomeMenuInit` (title "Welcome to Generals Online, %s", MOTD from `NGMP_OnlineServicesManager::GetMOTD`). `WOLWelcomeMenuSystem`: `buttonLobbyID` (`WOLWelcomeMenu.wnd:ButtonCustomMatch`) sets `nextScreen = "Menus/WOLCustomLobby.wnd"`; `buttonQuickMatchID` -> `Menus/WOLQuickMatchMenu.wnd` (matchmaking); `buttonLadderID` -> `Menus/WOLLadderScreen.wnd`; Back sets `SetPendingFullTeardown(EGOTearDownReason::USER_REQUESTED_SILENT)`.
5. **Lobby list screen.** `Menus/WOLLobbyMenu.cpp` (layout `WOLCustomLobby.wnd`): `WOLLobbyMenuInit` registers `NGMP_WOLLobbyMenu_CreateLobbyCallback` and `NGMP_WOLLobbyMenu_JoinLobbyCallback`. `WOLLobbyMenuUpdate` calls `refreshGameList(false)` when `NGMP_OnlineServices_LobbyInterface::IsLobbyListDirty()`. `refreshGameList` -> `RefreshGameListBoxes` -> `RefreshGameListBox` (`Core/GameEngine/Source/GameNetwork/GameSpy/LobbyUtils.cpp`). Chat rooms are `NGMP_OnlineServices_RoomsInterface` (`JoinRoom`, `GetGroupRooms`). Back: `ExitState()` (leaves the room, returns to the welcome screen).
6. **Create lobby.** Host button opens `GameSpyOpenOverlay(GSOVERLAY_GAMEOPTIONS)` -> `Menus/PopupHostGame.cpp` (layout `PopupHostGame.wnd`). `PopupHostGameInit` pre-fills the name from `CustomMatchPreferences::getLastLobbyName` (default "Generals Online Lobby"). `ButtonCreateGame` -> `createGame()` -> `NGMP_OnlineServices_LobbyInterface::CreateLobby(name, map display name, map file, isOfficial, numPlayers, limitArmies, useStats, starting cash, passworded, password, allowObservers)`. `CreateLobby` (`GO/OnlineServices_LobbyInterface.cpp`) sends HTTP PUT to `Lobbies` with JSON fields: `name`, `map_name`, `map_path`, `map_official`, `max_players`, `preferred_port` (always 0), `vanilla_teams`, `track_stats`, `starting_cash`, `passworded`, `password`, `allow_observers`, `exe_crc`, `ini_crc`, `max_cam_height`, `anticheat_id`. The ladder combo box is still filled (`PopulateCustomLadderComboBox`) but its value is not sent. Result: `NGMP_WOLLobbyMenu_CreateLobbyCallback` -> `nextScreen = "Menus/GameSpyGameOptionsMenu.wnd"`.
7. **Join lobby.** `WOLLobbyMenuSystem`, branch `controlID == buttonJoinID`: resolves the row with `ResolveGameListLobbyID`, `GetLobbyFromID`, refuses on `exe_crc`/`ini_crc` mismatch (with `VANILLA_INI_CRC` messages), `SetLobbyTryingToJoin`, then either `GameSpyOpenOverlay(GSOVERLAY_GAMEPASSWORD)` (`Menus/PopupJoinGame.cpp`, `joinGame()` -> `JoinLobby(lobby, password)`) or `JoinLobby(Lobby, "")` directly. `NGMP_WOLLobbyMenu_JoinLobbyCallback` handles `EJoinLobbyResult` and on success goes to `Menus/GameSpyGameOptionsMenu.wnd`.
8. **Staging screen.** `Menus/WOLGameSetupMenu.cpp` (layout `GameSpyGameOptionsMenu.wnd`), `WOLGameSetupMenuInit`, `WOLGameSetupMenuUpdate`, `WOLGameSetupMenuSystem`. The game state object is `NGMPGame` (`GO/NGMPGame.cpp`, global `TheNGMPGame`, also `NGMP_OnlineServices_LobbyInterface::GetCurrentGame()`), synced from the service by `NGMPGame::SyncWithLobby` / `UpdateSlotsFromCurrentLobby`. Lobby members are connected peer-to-peer in the staging room through `NetworkMesh` (GameNetworkingSockets with ICE/WebRTC and TURN credentials from the service, `NetworkMesh::StartConnectionSignalling`, `SetTurnCredentials`).
9. **Accept (non-host).** `WOLGameSetupMenuSystem`, branch `controlID == buttonStartID` when `!pLobbyInterface->IsHost()`: `localSlot->setAccept()` then `ApplyLocalUserPropertiesToCurrentNetworkRoom()`, which sends `WebSocket::SendData_MarkReady` (`GO/OnlineServices_LobbyInterface.cpp`). Auto-accept is compiled out (`GENERALS_ONLINE_DISABLE_AUTO_ACCEPT`).
10. **Host Start.** Same branch with `IsHost()` -> `StartPressed()`: checks readiness/map, then `WebSocket::SendData_StartFullMeshConnectivityCheck`. When the service reports a full mesh, `TheNGMPGame->StartCountdown()` (`GENERALS_ONLINE_ENABLE_MATCH_START_COUNTDOWN` is defined; sends `SendData_CountdownStarted`). `WOLGameSetupMenuUpdate` announces the seconds, locks settings at 1 s (`WOLLockSettings`), and at 0 sends `WebSocket::SendData_StartGame()`. (The `Lobby_StartGamePacket` / `SendToMesh` branch in `StartPressed` is inside `#if !defined(GENERALS_ONLINE_ENABLE_MATCH_START_COUNTDOWN)` and is dead.)
11. **Match launch (all players).** The service answers the start on the WebSocket; `GO/OnlineServices_RoomsInterface.cpp` (WebSocket message switch, `WebSocketMessage_StartGameResponse`) calls `pLobbyInterface->m_callbackStartGamePacket()`, registered in `WOLGameSetupMenuInit` via `RegisterForGameStartPacket`: copies the lobby game into `TheNGMPGame` and calls `NGMPGame::startGame(0)` -> `NGMPGame::launchGame()`:
    `TheNetwork = NetworkInterface::createNetwork(); TheNetwork->init(); TheNetwork->SeedLatencyData(mesh max latency); TheNetwork->setLocalAddress(...); TheNetwork->initTransport(); TheNetwork->parseUserList(this);` then `DoAnyMapTransfers`, `MSG_NEW_GAME` with `GAME_INTERNET`, `InitRandom(getSeed())`. `GameLogic.cpp` (`GeneralsMD/.../GameLogic/System/GameLogic.cpp`, start-of-game slot setup) uses `TheGameInfo = TheNGMPGame` when `TheNetwork && !TheLAN`.
12. **Match.** Lockstep `Network`/`ConnectionManager` (Core) unchanged in principle; transport is `NextGenTransport` over the lobby `NetworkMesh` (`ConnectionManager::initTransport`: `NextGenTransport` when `TheLAN == nullptr`, `UDPTransport` otherwise). Run-ahead logic heavily modified (`ConnectionManager::updateRunAhead`, service config `ra_*` values).
13. **Score screen.** `Core/GameEngine/Source/GameLogic/System/GameLogicDispatch.cpp` pushes `Menus/ScoreScreen.wnd`. `Menus/ScoreScreen.cpp`: stats via `NGMP_OnlineServices_StatsInterface`; match link (`buttonContinue` relabelled "VIEW MATCH ONLINE", hidden when `match_id == 0`); ladder result reporting is compiled out (`#if !defined(GENERALS_ONLINE)` around `TheGameSpyGame->getLadderPort()`).
14. **Return.** ScoreScreen OK -> `TheShell->pop()` back to the staging layout; `WOLGameSetupMenuInit` sees `TheNGMPGame->isGameInProgress()`, calls `LeaveCurrentLobby()`, `popImmediate()` and pushes `Menus/WOLCustomLobby.wnd`. Leaving the staging room manually: `PopBackToLobby()` (`LeaveCurrentLobby`, `nextScreen = "Menus/WOLCustomLobby.wnd"`).

Full teardown of the online session: `NGMP_OnlineServicesManager::SetPendingFullTeardown(EGOTearDownReason::...)`, executed later in `GameEngine::update` (`g_bTearDownGeneralsOnlineRequested` -> `NGMP_OnlineServicesManager::DestroyInstance()`).

## 2. Lobby list

- **Request:** `RefreshGameListBox(GameWindow*, Bool)` in `Core/GameEngine/Source/GameNetwork/GameSpy/LobbyUtils.cpp` calls `NGMP_OnlineServices_LobbyInterface::SearchForLobbies(onStart, onComplete)`. `SearchForLobbies` (`GO/OnlineServices_LobbyInterface.cpp`) does HTTP GET `Lobbies` and parses `lobbies[]` into `LobbyEntry` (fields `LobbyID, Owner, Name, MapName, MapPath, IsMapOfficial, NumCurrentPlayers, MaxPlayers, IsVanillaTeamsOnly, StartingCash, IsLimitSuperweapons, IsTrackingStats, IsPassworded, AllowObservers, MaximumCameraHeight, ExeCRC, IniCRC, MatchID, LobbyType, Region`, members with `Region`), plus `latencies[]` (one per lobby, by index) and `playerlatencies[]`.
- **Row insert:** static `insertGame(GameWindow*, LobbyEntry&, Bool showMap)` in `LobbyUtils.cpp`, called from the `onComplete` lambda inside `RefreshGameListBox`, after sorting into a `std::multiset<LobbyEntry, GameSortStruct>`.
- **Best place to filter rows:** the `onComplete` lambda of `RefreshGameListBox`, at the existing game-mode filter block (`if (theLobbyFilter != LOBBY_FILTER_ALL) { ... vecLobbies = filtered; }`), before `populateBuddyGames`/sorting. That block already does exactly this kind of filtering (`detectGameMode(name)`, `lobbyHasBuddy`). The filter UI is the room combo box: `PopulateLobbyFilterComboBox` in `WOLLobbyMenu.cpp` appends "Filter: All / 1v1 / Team Games / FFA / AOD / Buddies" entries to `comboLobbyGroupRooms`; selection handled in `WOLLobbyMenuSystem` `GCM_SELECTED`. Enum `LobbyGameModeFilter` in `Core/GameEngine/Include/GameNetwork/GameSpy/LobbyUtils.h`.
- **Hosting fields:** filled in `NGMP_OnlineServices_LobbyInterface::CreateLobby` (JSON listed in section 1, step 6), arguments supplied by `createGame()` in `Menus/PopupHostGame.cpp`. After creation, settings change through `UpdateCurrentLobby_*` (HTTP to `Lobby/<id>`). There is **no free-text field other than `name`** that the client can set, and no ladder/tag field. Adding a tag field needs a service change; without one, the only client-controlled carrier is the lobby name (or misuse of a numeric field such as `max_cam_height` - not recommended).
- **Region / latency already present:** yes.
  - `LobbyEntry::region` (service-supplied, JSON `Region`; not sent by `CreateLobby`, so presumably the host's region assigned by the service - not verified) and `LobbyEntry::latency` (from `latencies[]`; what it measures is decided by the service - not verified).
  - `LobbyMemberEntry::region`, `::latency`.
  - Displayed: `insertGame` writes `latency` into `COLUMN_PING` with ping images (`<250`, `<500`); `gameTooltip` shows "Region: %s" and "Latency: %d (%d frames)" (`ConvertMSLatencyToGenToolFrames`) and per-member "[region, N ms latency]".
  - The ladder column (`COLUMN_LADDER`) is still drawn but `insertGame` hard-codes `ladder = "TODO_NGMP"`, so it shows "no ladder"; this column is free to reuse for a "Server" label.
  - Sort buttons repurposed: `GrabWindowInfo` relabels `ButtonSortAlpha` "Sort by Newest", `ButtonSortPing` "Sort by Map".

## 3. Adding one main-menu button

- **Binding:** by window name: `TheNameKeyGenerator->nameToKey("MainMenu.wnd:ButtonOnline")`, `TheWindowManager->winGetWindowFromId(parentMainMenu, id)` in `MainMenuInit`; clicks compared by `controlID` in `MainMenuSystem` (`GBM_SELECTED`).
- **`.wnd` files:** not in the repository (`git ls-files` has no `*.wnd`, `*.str`, `*.csf`, `*.big`). They come from the game's data archives. Generals Online ships no `.wnd` changes in this repository (not verified whether its installer ships data files).
- **How Generals Online changes UI without new `.wnd` files** (all runtime manipulation of existing controls):
  - Repurpose an existing control: `ComboBoxGroupRooms` holds rooms plus filter entries (`PopulateLobbyFilterComboBox`, `WOLLobbyMenu.cpp`); `ButtonSortPing` relabelled (`GrabWindowInfo`, `LobbyUtils.cpp`, `winSetText`); `ScoreScreen.wnd:ButtonContinue` becomes "VIEW MATCH ONLINE" (`ScoreScreen.cpp`); `buttonDeleteAccount` becomes "LOGOUT" (`PopupPlayerInfo.cpp`); `WOLQuickMatchMenu.cpp` relabels start/stop as "START MATCHMAKING"/"CANCEL MATCHMAKING".
  - Move and unhide a hidden control: `PopupHostGameInit` moves `CheckBoxAllowObservers` to the stats check box column and `winHide(false)`; sets `EntryData::secretText` and `maxTextLen` on the password entry.
  - Creating a brand-new control at runtime: Generals Online has no example; the engine pattern is `TheWindowManager->gogoGadgetPushButton(parent, status, x, y, w, h, &instData, font, TRUE)` (debug buttons in `MainMenuInit` and `ReplayMenuInit`). The earlier work's `initServersButton` (`git show servers:.../MainMenu.cpp`) clones `ButtonNetwork`'s draw data and shifts siblings down; `MainMenuInit` on `servers-go` is close to upstream, so this function can be re-applied.
- **Player-facing text:** mostly hard-coded wide strings, no new string-file entries:
  - `UnicodeString(L"...")` everywhere (e.g. `GSMessageBoxOk(UnicodeString(L"Logging In"), UnicodeString(L"Login failed."))` in `NGMP_WOLLoginMenu_LoginCallback`; "Searching for public lobbies..." in `RefreshGameListBox`; "Please enter a lobby name." in `PopupHostGameSystem`).
  - `TheGameText->fetchOrSubstitute("GUI:Key", L"fallback")` (`Core/GameEngine/Include/GameClient/GameText.h`; e.g. `StartPatchCheck` "GUI:NoARMSupport", "GUI:ACErrorHeader"; `NGMP_WOLLobbyMenu_JoinLobbyCallback` "GUI:JoinFailedAnticheatMismatch"). This is the best choice for new text: a real label can be added later, the fallback works today.
  - Existing labels reused via `TheGameText->fetch` (e.g. "LAN:GameStartTimerPlural" for the countdown). Note the earlier work's `TheGameText->fetch("GUI:Servers")` requires the label in the string file; switch to `fetchOrSubstitute`.

## 6. GameSpy path and lobby hooks

- **Compiled, not reachable.** All GameSpy sources are still in `Core/GameEngine/CMakeLists.txt` `GAMEENGINE_SRC` and link `gamespy::gamespy`. In GO, `startOnline` skips `SetUpGameSpy` (`#if !defined(GENERALS_ONLINE)`), and the remaining `SetUpGameSpy` calls in `WOLLoginMenuUpdate` are inside a comment block, so `TheGameSpyInfo`, `TheGameSpyPeerMessageQueue` stay null. The `WOL*` menu files and `.wnd` layouts are reused but their bodies call `NGMP_*` interfaces. `TheGameSpyGame` is still used by `WOLQuickMatchMenu.cpp` and `GameSpyGameInfo.cpp`, but custom lobbies use `TheNGMPGame`. `LadderDefs`/`TheLadderList` still exist (used by `insertGame`), but no ladder value comes from the service.
- **Hook equivalents:**

| Earlier lobby piece | Generals Online hook |
|---|---|
| Tag in ladder fields at create | `createGame()` (`PopupHostGame.cpp`) -> `NGMP_OnlineServices_LobbyInterface::CreateLobby` JSON. No ladder field; use `name` or a new service field. `LobbyEntry::region` already exists, service-assigned |
| Lobby list filter | `RefreshGameListBox` `onComplete` lambda, `theLobbyFilter` block (`LobbyUtils.cpp`); UI in `PopulateLobbyFilterComboBox` (`WOLLobbyMenu.cpp`) |
| Join refusal for a foreign tag | `WOLLobbyMenuSystem`, `buttonJoinID` branch, next to the CRC check; also `joinGame()` in `PopupJoinGame.cpp` (password path) |
| Private message carrying join tokens | No generic private lobby message. Candidates: the lobby `NetworkMesh` (direct P2P link to each member, already required by the full-mesh check): `NetworkMesh::SendGamePacket(buf, size, userID)` / `PlayerConnection::SendACPacket` with a new `ENetworkChannel` value, dispatched in the receive loop in `NetworkMesh.cpp` (`ENetworkChannel netChannel = vecData[0]`); or `WebSocket::SendData_FriendMessage(msg, target_user_id)` (service may restrict to friends - not verified); or let the relay authorize by Generals Online user id/lobby id instead of tokens (needs service-to-relay trust) |

## 7. Multi-instance testing and offline play

- `RTS_MULTI_INSTANCE`: set automatically in any `_DEBUG` (Debug configuration) build by `NextGenMP_defines.h`, or in any build with CMake `-DRTS_DEBUG_MULTI_INSTANCE=ON` (`cmake/config-debug.cmake`). `rts::ClientInstance::initialize` (`Core/GameEngine/Source/GameClient/ClientInstance.cpp`) then numbers instances via named mutexes; per-instance files: `Options_Instance%.2u.ini` (`OptionPreferences.cpp`), log names (`Debug.cpp`), replays (`Recorder.cpp`), `GameSpyLogin_Instance%.2u.ini` (`WOLLoginMenu.cpp`), LAN prefs (`LanLobbyMenu.cpp`); `IPEnumeration.cpp` adds a `127.x.y.z` address per instance. `-replay` also forces multi-instance (`parseReplay` in `CommandLine.cpp`).
- Caveat: a Debug build talks to the DEV service at `https://localhost:9000` (`GetAPIEndpoint`), which is not in the repo. To test the online path with two instances on the live service you need a Release build with `-DRTS_DEBUG_MULTI_INSTANCE=ON` (PROD; both instances share `GeneralsOnlineData/credentials.json`, so separate accounts per instance are not supported without code changes - not verified), or `USE_TEST_ENV`/`USE_DEBUG_ON_LIVE_SERVER` edits in `NextGenMP_defines.h`. The version check sends the exe CRC; how PROD treats a self-built exe is not verified.
- Useful flags (`GeneralsMD/Code/GameEngine/Source/Common/CommandLine.cpp`): `-win`, `-fullscreen`, `-xres`, `-yres`, `-nologo`, `-noShellAnim`, `-quickstart`, `-headless`, `-replay`, `-mod`, `-NetCRCInterval`; GO adds `-exportStats`, `-statsUrl`, `-disableCommunityDataPatch`. No Generals Online flags for environment, account or direct match start.
- Without the online service: the LAN path is intact. `MainMenuSystem` `networkID` pushes `Menus/LanLobbyMenu.wnd`; `ConnectionManager::initTransport` uses `UDPTransport` when `TheLAN != nullptr`; `GameLogic.cpp` uses `TheLAN->GetMyGame()`. Skirmish and replays are unaffected. Whether a GO-built LAN match runs end to end is not verified. The earlier work's `-servers*` flags would give a lobby-free relay start once `ServersDirect.cpp` is adapted (section 5).
